# Locally generated Thistlethwaite pattern databases

These four exact databases are generated by this project's own C++ reverse-BFS builder in `PhasePatternDatabases.cpp`. No external solver or database-generation module is called.

| File | Transition coordinate | Entries | Exact maximum | Zero coordinates |
|---|---|---:|---:|---:|
| `phase1_edges.pdb` | orientations of 11 independent edges | 2,048 | 7 | 1 |
| `phase2_corners_eslice.pdb` | 7 corner orientations and positions of the four E-slice edges | 1,082,565 | 10 | 1 |
| `phase3_tetrads_slices.pdb` | ordered corner pairs, M/S edge-slice placement, and parity | 352,800 | 13 | 12 |
| `phase4_halfturn.pdb` | exact permutations inside the half-turn group | 663,552 | 15 | 1 |

The phase-3 coordinate deliberately stores 352,800 corner-pair/slice/parity encodings and treats all 12 encodings belonging to the half-turn group as simultaneous goals. Dividing by those 12 goal encodings gives the classical 29,400 G2/G3 quotient classes while keeping indexing simple and perfect.

Each file contains a 32-byte versioned header followed by one exact distance byte per coordinate. The header records the phase, entry count, maximum distance, and an FNV-1a checksum. A file is rejected and regenerated if any field, size, checksum, maximum, or goal count is wrong.

Generation starts from the solved cube. The phase-4 half-turn group is enumerated first; its 663,552 concrete states identify the 12 valid phase-3 goal coordinates. Reverse BFS then fills every coordinate under the move set allowed for that transition. Before a table is saved, the builder verifies every representative transition has a distance difference of at most one.

Delete any of these four files and run the solver to regenerate all four deterministically. `SHA256SUMS` contains the hashes produced by the checked-in generator.
